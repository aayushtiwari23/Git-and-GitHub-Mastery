# GitHub Issues

## Introduction

GitHub Issues are used to track bugs, feature requests, tasks, and project improvements. They provide a structured way for developers and contributors to discuss work before making changes.

Almost every professional open-source project uses Issues to manage development.

---

# What is an Issue?

An Issue is a discussion thread created inside a GitHub repository.

It can be used to:

- Report bugs
- Request new features
- Suggest improvements
- Ask questions
- Assign tasks

Each Issue has its own title, description, comments, labels, and status.

---

# Why Use Issues?

Issues help teams:

- Organize work
- Track bugs
- Plan new features
- Assign tasks
- Discuss solutions
- Maintain project history

---

# How to Create an Issue

### Step 1

Open a GitHub repository.

### Step 2

Click the **Issues** tab.

### Step 3

Click **New Issue**.

### Step 4

Enter a clear title.

Example:

```text
Fix Login Button Alignment
```

### Step 5

Write a detailed description.

Example:

```text
The login button is misaligned on mobile devices.

Expected:
Button should be centered.

Actual:
Button appears on the left side.
```

### Step 6

Click **Create Issue**.

---

# Issue Components

A typical Issue contains:

- Title
- Description
- Labels
- Assignees
- Comments
- Status (Open / Closed)

---

# Example Issue

Title:

```text
Add Dark Mode Support
```

Description:

```text
Implement a dark mode theme across the application.

Requirements:

- Dark background
- Light text
- Toggle button
```

---

# Open vs Closed Issues

| Open | Closed |
|------|--------|
| Work is pending | Work is completed |
| Visible in Open Issues | Moved to Closed Issues |

---

# Real-World Example

A user finds that the search feature crashes when entering special characters.

Instead of sending a message privately, they create an Issue.

Developers discuss the problem, assign it to a team member, fix it, and close the Issue.

---

# Best Practices

- Write clear titles.
- Provide enough details.
- Include screenshots when needed.
- One Issue should focus on one problem.
- Close Issues after they are resolved.

---

# Common Mistakes

- Using vague titles.
- Reporting multiple problems in one Issue.
- Not providing reproduction steps.
- Closing Issues before verification.

# Interview Questions

### What is a GitHub Issue?

---

### Can anyone create an Issue?

Yes, if the repository settings allow it.

---

### What is the difference between an Open and Closed Issue?

Open means work is pending.

Closed means the issue has been resolved or completed.

---

They help teams organize, discuss, and track project work efficiently.
