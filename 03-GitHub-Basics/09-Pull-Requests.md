
# Pull Requests

## Introduction

A Pull Request (PR) is a request to merge changes from one branch or repository into another. It allows developers to review code, discuss improvements, and approve changes before they become part of the main project.

Pull Requests are one of the most important features of GitHub and are used in almost every professional software team.

---

# What is a Pull Request?

A Pull Request is a proposal to merge your changes into another branch or repository.

It allows:

- Code Review
- Team Discussion
- Feedback
- Testing
- Approval before merging

---

# Why Use Pull Requests?

Pull Requests help developers:

- Review code
- Prevent bugs
- Improve code quality
- Collaborate safely
- Track project changes

---

# Pull Request Workflow

```text
Create Branch
      │
Make Changes
      │
Commit Changes
      │
Push Branch
      │
Open Pull Request
      │
Code Review
      │
Approve Changes
      │
Merge
```

---

# How to Create a Pull Request

### Step 1

Create a new branch.

### Step 2

Make your changes.

### Step 3

Commit the changes.

### Step 4

Push the branch to GitHub.

### Step 5

Open your repository.

### Step 6

Click **Compare & Pull Request**.

### Step 7

Add:

- Title
- Description

### Step 8

Click **Create Pull Request**.

---

# Pull Request Components

Every Pull Request contains:

- Title
- Description
- Commits
- Changed Files
- Comments
- Review Status

---

# Example

Title:

```text
Add Login Authentication
```

Description:

```text
This Pull Request adds user authentication using JWT.

Changes:
- Login API
- Password Hashing
- Validation
```

---

# Pull Request vs Commit

| Commit | Pull Request |
|---------|--------------|
| Saves changes | Requests merging changes |
| Local history | Collaboration feature |
| Individual snapshot | Collection of commits |

---

# Real-World Example

A developer completes the Payment Module.

Instead of merging directly into `main`, they create a Pull Request.

Other developers review the code, suggest improvements, approve it, and then merge it.

---

# Best Practices

- Keep Pull Requests small.
- Write a clear title.
- Explain your changes.
- Respond to review comments.
- Test your code before creating a PR.

---

# Common Mistakes

- Creating very large Pull Requests.
- Not explaining the changes.
- Ignoring review comments.
- Merging without testing.
