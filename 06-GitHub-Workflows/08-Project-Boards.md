# GitHub Project Boards

## Introduction

GitHub Project Boards (now called **GitHub Projects**) are project management tools built into GitHub. They help individuals and teams organize tasks, track progress, assign work, and manage software development using Kanban-style boards, tables, and roadmaps.

Many companies and open-source projects use GitHub Projects to plan releases and coordinate development.

---

# What are GitHub Projects?

GitHub Projects provide a centralized workspace where developers can manage issues, pull requests, and tasks.

A project can include:

- Issues
- Pull Requests
- Draft Tasks
- Custom Fields
- Progress Tracking
- Roadmaps

---

# Why Use GitHub Projects?

Developers use GitHub Projects to:

- Plan features
- Track bugs
- Organize tasks
- Monitor project progress
- Collaborate with teams
- Manage releases

---

# Project Board Workflow

```text
Ideas
  │
  ▼
To Do
  │
  ▼
In Progress
  │
  ▼
Review
  │
  ▼
Testing
  │
  ▼

```

---

# Common Board Columns

## 1. Backlog

Tasks planned for future development.

Example:

- Dark Mode
- Payment Gateway
- User Dashboard

---

## 2. To Do

Tasks ready to begin.

Example:

- Design Login Page
- Fix Navbar
- Update README

---

## 3. In Progress

Tasks currently being developed.

---

## 4. Review

Completed work waiting for code review.

---

## 5. Testing

Features being tested before release.

---

## 6. Done

Completed and merged tasks.

---

# Creating a Project

### Step 1

Open your GitHub repository.

---

### Step 2

Click:

```text
Projects
```

---

### Step 3

Click:

```text
New Project
```

---

### Step 4

Choose a template.

Examples:

- Board
- Table
- Roadmap

---

### Step 5

Give your project a name.

Example:

```text
Portfolio Website
```

---

# Adding Tasks

You can add:

- Draft Tasks
- GitHub Issues
- Pull Requests

Example Draft Tasks:

```text
Create Login Page

Build API

Add Documentation

Write Unit Tests
```

---

# Linking Issues and Pull Requests

Example:

Issue:

```text
#15 Fix Login Validation
```

Pull Request:

```text
#28 Fix Login Validation
```

When the Pull Request is merged, GitHub can automatically close the linked issue.

---

# Automation

GitHub Projects supports automation.

Examples:

- Move a task to **In Progress** when work starts.
- Move a task to **Review** when a Pull Request is opened.
- Move a task to **Done** after merging.

---

# Best Practices

- Break large features into smaller tasks.
- Keep task names descriptive.
- Update task status regularly.
- Link Pull Requests to Issues.
- Archive completed projects.

---

# Common Mistakes

- Creating tasks that are too large.
- Forgetting to update status.
- Using unclear task names.
- Ignoring completed tasks.
- Mixing unrelated work in one project.
